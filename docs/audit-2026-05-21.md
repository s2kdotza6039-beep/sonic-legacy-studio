# Full Music Platform Audit — 2026-05-21

End-to-end probe of R2, frontend, edge functions, PayFast, and DB.

## Production readiness score: **52 / 100** — NOT production-ready

Two showstoppers (Worker not deployed, signed URL missing protocol) plus a key-encoding mismatch that will break playback the moment the Worker is enabled.

---

## 1. CRITICAL — fix before any user touches the site

### ❌ C1. Cloudflare Worker is NOT deployed in front of R2
**Evidence:** `GET https://newsingle.s2kdotza.com/KULE%20LIFE%20-%20PBA%20edit.mp3` (no token, no signature) returns `200 OK, 6 737 124 bytes, audio/mpeg`. The full file streams. The `t=` param is ignored entirely. `cf-cache-status: MISS` + default `cache-control: max-age=14400` confirms it's hitting the R2 public binding directly.

**Impact:** Every track is fully downloadable by anyone. The whole tier model (25 % / 55 % / 100 %) is bypassed. PayFast revenue is bypassable.

**Fix:** Deploy the Worker in `docs/payments-setup.md` to the route `newsingle.s2kdotza.com/*` and remove the R2 bucket's public domain binding (or move objects to a private bucket). Then re-test: an unsigned GET must return `401 missing token`.

### ❌ C2. Stream-track returned a URL without `https://`
**Evidence:** `stream-track` returned `"url":"newsingle.s2kdotza.com/KULE...mp3?t=..."`. The `R2_PUBLIC_BASE` secret was saved without the scheme. In a browser, `<audio src="newsingle.s2kdotza.com/...">` is treated as a path relative to `s2kdotza.com`, so playback would 404.

**Fix applied this turn:** `stream-track/index.ts` now defensively prepends `https://` if the secret omits it. **Also recommended:** edit the secret value to start with `https://`.

### ⚠ C3. R2 object keys are URL-encoded in the `tracks` table
**Evidence:** `r2_object_key = 'KULE%20LIFE%20-%20PBA%20edit.mp3'`. The Worker (`docs/payments-setup.md`) does `decodeURIComponent(url.pathname.replace(/^\/+/, ""))` → `"KULE LIFE - PBA edit.mp3"`, then compares against the token's `p` field which contains the literal `'KULE%20LIFE%20...'`. **Path-mismatch 403 the moment the Worker is live.**

**Fix:** Pick one and stick to it.
  - Option A (recommended): store the raw key — `KULE LIFE - PBA edit.mp3` — in `tracks.r2_object_key`. Encode only at URL-build time.
  - Option B: change the Worker so the token's `p` is also `decodeURIComponent`-ed before comparison.

Run once Option A is chosen:
```sql
UPDATE tracks SET r2_object_key = replace(r2_object_key, '%20', ' ');
```

## 3. Warnings ⚠

- **W1.** No PayFast ITN has ever landed (`payfast_notify_log` is empty, `payments.status` only ever `pending`). The full ITN → unlock loop has not been exercised against the real PayFast sandbox host. Use `/sandbox/payments` while logged in as the founder before going live.
- **W2.** Five orphan `pending` payments. Add a scheduled job to expire pending rows older than ~30 min so the unique-`m_payment_id` audit stays clean.
- **W3.** R2 responses currently send `cache-control: max-age=14400` (CF default). Once the Worker is in place its `private, no-store` will override — verify after deploy.
- **W4.** No CORS preflight handling on R2 (`OPTIONS` returned 403). HTML5 `<audio>` does not preflight `Range` requests, so this is OK today — but if you ever fetch via `fetch()`/Web Audio API, the Worker must add CORS.
- **W5.** Download token TTL is 10 minutes (`payfast-notify`) and stream token TTL is 5 minutes (`stream-track`). Fine, but surface the countdown on the Listen page (already implemented) — make sure it matches.
